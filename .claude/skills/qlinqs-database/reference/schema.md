# Full schema reference

Verified live against `qlinqs_core_api` via `docker compose exec db psql -U
qlinqs -d qlinqs_core_api -c '\d <table>'` and cross-checked with `php
artisan db:table <table>` inside the `app` container — both agreed exactly.
Source migrations: `database/migrations/2026_09_15_100000_…` through
`…_100006_…` (plus the default `0001_01_01_…` Laravel/Sanctum migrations for
`users`, `sessions`, `personal_access_tokens`, etc., unchanged from
scaffolding and not repeated here).

## `users`

| Column | Type | Nullable | Default |
|---|---|---|---|
| `id` | uuid (PK) | no | — (app-generated via `HasUuids`) |
| `name` | varchar(255) | no | |
| `email` | varchar(255) | no | |
| `email_verified_at` | timestamp **without** tz | yes | |
| `password` | varchar(255) | no | |
| `remember_token` | varchar(100) | yes | |
| `created_at` | timestamp **without** tz | yes | |
| `updated_at` | timestamp **without** tz | yes | |

- PK: `users_pkey (id)`. Unique: `users_email_unique (email)`.
- Referenced by: `profiles.user_id`.
- No timezone on any timestamp here — every other table below uses
  `timestamptz`. Inherited from the Laravel skeleton's default
  `$table->timestamps()`, not deliberate for this project.
- This is the conceptual doc's `auth_users`, modeled locally (no external
  auth provider). No login/registration/token-issuing flow exists yet.

## `profiles`

| Column | Type | Nullable | Default |
|---|---|---|---|
| `id` | uuid (PK) | no | — (app-generated) |
| `user_id` | uuid, FK → `users.id` | no | |
| `created_at` | timestamptz | no | `CURRENT_TIMESTAMP` |
| `updated_at` | timestamptz | yes | |
| `slug` | **citext** | no | |

- PK: `profiles_pkey (id)`. Unique: `profiles_slug_unique (slug)`,
  `profiles_user_id_unique (user_id)` — one profile per user.
- FK: `profiles_user_id_foreign (user_id) → users(id)` — **no `ON DELETE`
  clause** (Postgres default: `NO ACTION`/restrict). Deleting a user that
  still has a profile fails.
- Referenced by: `assets.profile_id` (cascade), `pages.profile_id` (cascade).
- `slug` is `citext` (added via raw SQL in the migration — Laravel's
  Blueprint has no built-in citext type), so comparisons are
  case-insensitive at the DB level.

## `pages`

| Column | Type | Nullable | Default |
|---|---|---|---|
| `id` | uuid (PK) | no | — (app-generated) |
| `profile_id` | uuid, FK → `profiles.id` | no | |
| `content` | jsonb | no | `'{}'::jsonb` |
| `theme` | jsonb | no | — (none) |
| `created_at` | timestamptz | no | `CURRENT_TIMESTAMP` |
| `updated_at` | timestamptz | yes | |

- PK: `pages_pkey (id)`. Unique: `pages_profile_id_unique (profile_id)` —
  one page per profile.
- FK: `pages_profile_id_foreign (profile_id) → profiles(id) ON DELETE
  CASCADE`.
- Referenced by: `block_clicks.page_id` (cascade), `page_views.page_id`
  (cascade).
- `content`'s DB default (`{}`) does not by itself satisfy
  `PageContentRules` — see `jsonb-shapes.md`. `theme` has no default at
  all; every page is created with a theme (default or copied from a
  template).

## `templates`

| Column | Type | Nullable | Default |
|---|---|---|---|
| `id` | uuid (PK) | no | — (app-generated) |
| `name` | text | no | |
| `preview` | text | no | |
| `theme` | jsonb | no | — (none) |
| `created_at` | timestamptz | no | `CURRENT_TIMESTAMP` |

- PK: `templates_pkey (id)`. Unique: `templates_name_unique (name)`.
- **No `updated_at` column.** No FK to/from `pages`, and no Eloquent
  relationship either — applying a template copies `theme` into
  `pages.theme`; editing/deleting a template afterward must never affect a
  page that already applied it.
- Populated by `database/seeders/TemplateSeeder.php` (4 starter templates).
  No create/update/delete endpoint exists.

## `assets`

| Column | Type | Nullable | Default |
|---|---|---|---|
| `id` | uuid (PK) | no | — (app-generated) |
| `profile_id` | uuid, FK → `profiles.id` | no | |
| `storage_path` | text | no | |
| `mime_type` | text | no | |
| `size_bytes` | bigint | no | |
| `width` | integer | no | |
| `height` | integer | no | |
| `created_at` | timestamptz | no | `CURRENT_TIMESTAMP` |

- PK: `assets_pkey (id)`. Unique: `assets_storage_path_unique
  (storage_path)`. Index: `assets_profile_id_index (profile_id)`.
- FK: `assets_profile_id_foreign (profile_id) → profiles(id) ON DELETE
  CASCADE`. Owned by the **profile**, not the page, so one upload can be
  reused across pages once multi-page support exists.
- **No `updated_at` column.** No upload endpoint exists yet — this table
  and model are fully built but nothing in the API writes to them.
  Cascade-deleting a profile removes the `assets` rows but **not** the
  object in the storage bucket — that's the application's job.

## `page_views`

| Column | Type | Nullable | Default |
|---|---|---|---|
| `id` | bigint (PK, **identity**) | no | `GENERATED BY DEFAULT AS IDENTITY` |
| `page_id` | uuid, FK → `pages.id` | no | |
| `viewed_at` | timestamptz | no | `CURRENT_TIMESTAMP` |

- PK: `page_views_pkey (id)`. Index: `page_views_page_id_viewed_at_index
  (page_id, viewed_at)`.
- FK: `page_views_page_id_foreign (page_id) → pages(id) ON DELETE CASCADE`.
- `id` is a real Postgres identity column (`GENERATED BY DEFAULT AS
  IDENTITY`), not a legacy `bigserial`/`nextval` sequence default — matters
  if you're introspecting via `information_schema.columns.is_identity`.
- No tracking endpoint exists yet; nothing writes here via the API.

## `block_clicks`

| Column | Type | Nullable | Default |
|---|---|---|---|
| `id` | bigint (PK, **identity**) | no | `GENERATED BY DEFAULT AS IDENTITY` |
| `page_id` | uuid, FK → `pages.id` | no | |
| `block_id` | text | no | — (no FK) |
| `clicked_at` | timestamptz | no | `CURRENT_TIMESTAMP` |

- PK: `block_clicks_pkey (id)`. Index:
  `block_clicks_page_id_block_id_clicked_at_index (page_id, block_id,
  clicked_at)`.
- FK: `block_clicks_page_id_foreign (page_id) → pages(id) ON DELETE
  CASCADE`. `block_id` is a **logical** reference into `pages.content`'s
  JSONB — no FK, by design; the DB can't enforce it, and the app tolerates
  clicks on a since-deleted block.
- No tracking endpoint exists yet.

## Extensions

```
$ docker compose exec db psql -U qlinqs -d qlinqs_core_api -c '\dx'
  Name   | Version |   Schema   |                   Description
---------+---------+------------+---------------------------------------------------
 citext  | 1.6     | public     | data type for case-insensitive character strings
 plpgsql | 1.0     | pg_catalog | PL/pgSQL procedural language
```

`citext` is enabled by `database/migrations/2026_09_15_100000_enable_citext_extension.php`,
which runs before the `profiles` migration (order matters — `profiles.slug`
depends on the type existing).
